# MCP Server

`@timeui/mcp` 是 TimeUI 的 **Model Context Protocol** 服务器：把全部组件文档封装成可调用的工具，让 Claude Code、Cursor、Windsurf 等 AI 客户端能直接查真实的组件 API、示例代码与分类结构，而不是从记忆里猜。

## 30 秒接入

一条命令把 TimeUI 接进 Claude Code：

```bash
claude mcp add timeui -- npx -y @timeui/mcp timeui-mcp
```

然后在对话里直接写真实需求：

> 帮我用 TimeUI 的 Form 组件做一个登录页。先告诉我 TimeUI 里有哪些表单组件。

Claude 会自动调用 MCP 工具去查当前发布版的真实 API、示例和分类，再动手写代码——不会瞎编 prop 名。其他 IDE（Cursor / Windsurf / Claude Desktop）的接入方式见下文 [安装 & 接入](#安装--接入)。

## 为什么需要它

AI 编辑器在推荐组件用法时，常见两种失败模式：

- **时效性失败** —— 训练时看到的是旧版 API，推荐的 prop 名或用法已经改过。
- **记忆失败** —— 根本没见过这个组件，AI 选择"编一个"。

MCP Server 把 TimeUI 的文档做成可调用接口，AI 每次回答时可以先查再答：你得到的是**当前发布版**里真实存在的 API 与示例，而不是 AI 的推测。

## 工具清单

工具按"问的是组件"还是"问的是怎么用"分两组。所有工具都支持 `locale` 参数（`zh` / `en`，默认 `zh`）。

**组件类（针对 packages/components 下 35 个 UI 组件）**

| 工具 | 用途 |
| --- | --- |
| `list_categories` | 列出所有组件分类（general / forms / overlays / …）以及每个分类下的组件数。 |
| `list_components` | 列出组件 slug / 标题 / 简介 / 分类，可选按 category 过滤。 |
| `get_component` | 按 slug 返回单个组件的完整文档：标题、描述、正文、示例代码、docs URL。 |
| `search_components` | 全文打分检索标题 / 描述 / 正文，返回带片段的命中列表。 |

**指南类（针对安装、接入、Chat API 等非组件文档）**

| 工具 | 用途 |
| --- | --- |
| `list_sections` | 列出所有指南 section（getting-started / chat …）以及每个 section 下的页面数。 |
| `list_guides` | 列出所有指南页（installation / introduction / mcp / overview / api…），可选按 section 过滤。 |
| `get_guide` | 按 slug 返回单个指南页的完整正文与示例代码。 |
| `search_guides` | 仅在指南域内打分检索；问"怎么安装"、"如何接入 SSE"、"chat API 在哪" 时用这个，不会召回组件。 |

## 实战对话示例

下面三个场景展示 AI 如何根据你的提问自己挑工具、自己串参数。你不需要手动调工具，只需要正常提问。

### 场景 A：探索类 —— "TimeUI 有哪些表单组件？"

AI 通常会先调 `list_categories` 拿到分类清单，再带 `category` 精确调 `list_components`：

```json
// 1. 先看分类
{ "name": "list_categories", "arguments": { "locale": "zh" } }
// → [{ "slug": "forms", "label": "表单", "componentCount": 11 }, ...]

// 2. 再拿 forms 分类下的组件
{ "name": "list_components", "arguments": { "locale": "zh", "category": "forms" } }
// → [{ "slug": "input", "title": "Input 输入框", "href": "/zh/docs/components/input" }, ...]
```

AI 回你的内容大致是："TimeUI 的 forms 分类里有 11 个组件，包括 Input、Textarea、Select、Checkbox、Radio、Switch…… 要我用哪些拼登录页？"

### 场景 B：精确查询类 —— "Button 的 variant 有哪些？"

AI 已经知道组件名了，直接用 `get_component` 读单页详情：

```json
{ "name": "get_component", "arguments": { "slug": "button", "locale": "zh" } }
```

返回对象里的 `content` 字段是完整正文（含 Props 表），`examples` 是 MDX 里抽出来的代码片段。AI 从里面直接摘出 `variant: 'solid' | 'soft' | 'light' | 'outline' | 'ghost' | 'link'` 这类信息，然后告诉你："Button 支持 6 种 variant，其中 `solid` 是默认值；下面是一个 `variant="light"` 的示例……"

### 场景 C：搜索类 —— "用来显示加载状态的组件叫什么？"

你没说组件名，AI 会用 `search_components` 模糊找：

```json
{ "name": "search_components", "arguments": { "query": "loading 加载", "locale": "zh", "limit": 5 } }
```

返回按打分排序的命中列表，每条带 snippet 上下文片段：

```json
[
  { "slug": "skeleton", "title": "Skeleton 骨架屏", "snippet": "…在内容加载时占位…", "score": 42 },
  { "slug": "button", "title": "Button 按钮", "snippet": "…loading 态会禁用点击…", "score": 18 }
]
```

AI 会挑分数最高的项（这里是 Skeleton），必要时再 `get_component` 取详情，最后回你："你要找的应该是 Skeleton（骨架屏）；如果只是按钮内部的 loading 态，Button 自己就有 `loading` prop。"

## 安装 & 接入

### Claude Code

```bash
claude mcp add timeui -- npx -y @timeui/mcp timeui-mcp
```

接入完成后，在对话里直接问 `TimeUI 有哪些表单组件？` 或 `Button 的 variant 有哪些？`，Claude 会自动调用对应工具。

### Cursor / Windsurf

在 `.cursor/mcp.json`（Cursor）或等价配置中加入：

```json
{
  "mcpServers": {
    "timeui": {
      "command": "npx",
      "args": ["-y", "@timeui/mcp", "timeui-mcp"]
    }
  }
}
```

### HTTP 形态（给远程客户端）

除了 stdio，也提供 Streamable HTTP transport，方便部署给远程 AI 客户端使用：

```bash
npx -y @timeui/mcp timeui-mcp-http --port 3333
# MCP endpoint: http://127.0.0.1:3333/mcp
```

默认绑定 `127.0.0.1` 避免意外暴露；需要对外监听时加 `--host 0.0.0.0`。

### Claude Desktop

Claude Desktop 目前的 MCP 集成仍然走 **stdio**（配置文件为 `claude_desktop_config.json`，macOS 位于 `~/Library/Application Support/Claude/claude_desktop_config.json`，Windows 位于 `%APPDATA%\Claude\claude_desktop_config.json`）。推荐直接用 `npx` 启动 stdio 进程：

```json
{
  "mcpServers": {
    "timeui": {
      "command": "npx",
      "args": ["-y", "@timeui/mcp", "timeui-mcp"]
    }
  }
}
```

保存后重启 Claude Desktop，就能在对话里看到 TimeUI 的工具被自动拉起来。

如果你已经在局域网 / 服务器上跑着 `timeui-mcp-http`，想用桌面端接它的 HTTP endpoint，可以借助社区的 stdio ↔ HTTP 适配器（例如 `mcp-remote` / `supergateway`）把远程 endpoint 反代成本地 stdio。以 `mcp-remote` 为例：

```json
{
  "mcpServers": {
    "timeui": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "http://your-host:3333/mcp"]
    }
  }
}
```

## 原理

- 构建期 `scripts/build-index.ts` 扫描 `apps/docs` 下所有 MDX，产出三份索引：包内 bundled 的 `data/index.json`（随 npm 发布）、`apps/docs/public/mcp-index.json`（完整版，部署时随 docs 上线）、`apps/docs/public/assistant-index.json`（精简版，前端 AI 助手用）。
- 启动期 `runStdio` / `runHttp` 会先尝试从远程 `mcp-index.json` 拉最新索引（默认 `http://aliyun.ryanstone.cn/mcp-index.json`，3 秒超时），失败 / 离线时回退包内 bundled 快照——所以你**不需要重装包**就能拿到最新的文档。
- stdio 模式下，每个 AI 客户端会话都会 `spawn` 一个 Node 进程，工具调用本地零网络（除启动那次远程刷新外）。
- HTTP 模式走 MCP Streamable HTTP 规范，支持多会话与断流重连。

### 自定义索引来源

通过环境变量切换索引来源：

```bash
# 指向自托管的 docs 站
TIMEUI_MCP_INDEX_URL=https://your-docs.example.com/mcp-index.json npx @timeui/mcp timeui-mcp

# 完全离线（只用包内 bundled 快照）
TIMEUI_MCP_INDEX_URL=off npx @timeui/mcp timeui-mcp
```

## 版本策略

- **核心组件 API**（`@timeui/react` 的 props / 行为）：跟随包版本，重大变更会通过 changeset 体现到 `@timeui/mcp` 的 changelog。
- **文档内容**（描述、示例、新增章节）：默认走运行时远程拉取，docs 站部署后 MCP 客户端**重启即生效**，不需要重新安装包。
- 完全不需要外网时，把 `TIMEUI_MCP_INDEX_URL` 设为 `off`，永远用包内 bundled 快照（旧版默认行为）。
