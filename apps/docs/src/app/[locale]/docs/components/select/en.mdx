# Select

A **custom listbox** dropdown (no longer a native `<select>`), visually matched
to [`Input`](./input) (same four variants × six colors × five sizes). Supports
**search filtering**, **max-height + scroll**, and full keyboard + screen-reader
access.

Two ways to pass options: the declarative `items` array (preferred), or
`<SelectOption>` children (whose props are read at render time — they don't
emit DOM themselves).

## Server-side search & pagination

`isSearchable` alone filters the `items` you already have. When the option set lives behind an API, Select can talk to it directly — with debounce, in-flight cancellation, infinite scroll and retry handled for you. There are three modes and they are fully backwards compatible:

| Mode | How you opt in | Who owns the data |
| --- | --- | --- |
| **Local** (default) | nothing to do | you pass `items` / `<SelectOption>`; the component filters |
| **Managed remote** | pass `loadOptions` | the component fetches, paginates and caches |
| **Controlled remote** | `searchMode="remote"` + your own `items` | you fetch; the component only renders |

### Managed remote (`loadOptions`)

Give Select an async loader and it takes care of the rest: the keyword is debounced (`searchDebounce`, 300 ms), each new query cancels the previous one via `AbortSignal`, out-of-order responses are discarded, scrolling to the bottom pulls the next page, and a failure shows an inline retry.

<LiveDemo previewSource="children" code={`import { Select } from '@timeui/react';

<Select
  label="Assignee"
  placeholder="Search users…"
  isSearchable
  isFullWidth
  value={assignee}
  onChange={setAssignee}
  pageSize={20}
  searchParams={{ dept }}
  loadOptions={async ({ keyword, page, pageSize, params, signal }) => {
    const res = await fetch(
      \`/api/users?q=\${encodeURIComponent(keyword)}&page=\${page}&size=\${pageSize}&dept=\${params.dept}\`,
      { signal },
    );
    const data = await res.json();
    return { items: data.list, hasMore: data.hasNext, total: data.total };
  }}
/>`}>
  <SelectRemoteSearchDemo />
</LiveDemo>

The loader receives everything it needs to build a request:

```ts
loadOptions: (req: {
  keyword: string;      // the debounced search term
  page: number;         // 1-based
  pageSize: number;     // from the `pageSize` prop (default 20)
  params?: Record<string, unknown>;  // whatever you put in `searchParams`
  reason: 'open' | 'search' | 'params' | 'loadMore' | 'retry';
  signal: AbortSignal;  // forward it to fetch to cancel superseded requests
}) => Promise<{ items: SelectItem[]; hasMore?: boolean; total?: number } | SelectItem[]>
```

Returning a bare array is fine — `hasMore` is then inferred from `items.length >= pageSize`.

### Extra query parameters

`searchParams` is merged into every request as `params`, and **changing it re-runs the search from page 1**. That is how you wire a Select to sibling filters (department, project, status…) without writing an effect.

```tsx
<Select isSearchable loadOptions={loadUsers} searchParams={{ dept, includeArchived }} />
```

### Pagination

Pages accumulate in order and are de-duplicated by `value`, so overlapping backend pages never produce duplicate rows. The next page is requested when the list scrolls within `loadMoreThreshold` (48 px) of the bottom — and also when keyboard navigation reaches the last option, so keyboard users can page through too.

### Controlled remote

If you already have a data layer (React Query, SWR, Redux…), keep it and let Select render:

```tsx
const [keyword, setKeyword] = useState('');
const { data, isLoading, isFetchingNextPage, hasNextPage, fetchNextPage, error, refetch } =
  useUsers(keyword);

<Select
  isSearchable
  searchMode="remote"          {/* skip local filtering */}
  items={data?.items ?? []}
  searchValue={keyword}
  onSearchChange={setKeyword}  {/* every keystroke */}
  onSearch={runQuery}          {/* debounced — fire the request here */}
  isLoading={isLoading}
  isLoadingMore={isFetchingNextPage}
  hasMore={hasNextPage}
  onLoadMore={fetchNextPage}
  loadError={error ? 'Could not load users' : undefined}
  onRetry={refetch}
/>
```

### Keeping the selected label

Remote results are replaced on every new query, so the selected option often is not in the current list. Select remembers the label of whatever you picked, and also looks into `items` — pass the already-known option there to render a preselected value that has not been fetched yet:

```tsx
<Select
  value={user.id}
  items={[{ value: user.id, label: user.name }]}  {/* known option for the initial render */}
  loadOptions={loadUsers}
  isSearchable
/>
```

<Callout variant="info" title="Accessibility">
  The trigger is `role="combobox"` + `aria-haspopup="listbox"` +
  `aria-expanded`; the popover is `role="listbox"`; options are
  `role="option"` with `aria-selected` / `aria-disabled`. Keyboard:
  `↑/↓` moves the highlight, `Home/End` jumps to the ends, `Enter` selects,
  `Space` selects (or opens when closed), `Esc` closes and returns focus.
  With `isSearchable` the search input is focused on open; focus returns to
  the trigger on close. Label / description / errorMessage wiring is handled
  by the implicit FormField.
</Callout>
