# Menu

A keyboard-navigable dropdown menu: anchored via Popover, supports both declarative (`<Menu.Item>` / `<Menu.Section>` / `<Menu.Divider>`) and data-driven (`items`) authoring, three selection modes (none / single / multiple), roving focus + type-to-jump, and per-item modifiers (shortcut, icon, description, danger, href).

<Callout variant="info" title="Menu vs. Popover">
  - **Menu** — a list of mutually exclusive commands (actions, navigations, toggles). Arrow-key roving, Enter to invoke, ARIA `menu` semantics.
  - **Popover** — a small card with arbitrary rich content (form, link list, hint text). No menu behaviour.
</Callout>

## Basic usage

`onAction(key)` fires whenever an item is invoked. Combine with `<Menu.Section>` for semantic grouping, `<Menu.Divider>` for visual separators, and `isDanger` for destructive actions.

<LiveDemo code={`<Menu
  trigger={<Button variant="bordered">Open menu</Button>}
  onAction={(key) => console.log(key)}
>
  <MenuSection label="Account">
    <MenuItem itemKey="profile" shortcut="⌘P">Profile</MenuItem>
    <MenuItem itemKey="settings" shortcut="⌘,">Settings</MenuItem>
  </MenuSection>
  <MenuDivider />
  <MenuItem itemKey="signout" isDanger>Sign out</MenuItem>
</Menu>`}>

## Multiple selection

With `selectionMode="multiple"`, clicking an item toggles its checked state and the menu stays open; a checkmark indicator renders on the right. `selectedKeys` / `defaultSelectedKeys` cover both controlled and uncontrolled use.

<LiveDemo previewSource="children" code={`const [selected, setSelected] = useState<Set<string>>(new Set(['inbox']));

<Menu
  trigger={<Button>Show columns</Button>}
  selectionMode="multiple"
  selectedKeys={selected}
  onSelectionChange={setSelected}
>
  <MenuItem itemKey="inbox">Inbox</MenuItem>

## Data-driven

Pass a flat `items` array to skip JSX in large menus. The two forms are interchangeable, but don't mix them within the same menu.

```tsx
<Menu
  trigger={<Button>Sort</Button>}
  selectionMode="single"
  defaultSelectedKeys={['name-asc']}
  items={[
    {
      type: 'section',
      sectionKey: 'name',
      label: 'Name',
      items: [
        { itemKey: 'name-asc', label: 'A → Z' },
        { itemKey: 'name-desc', label: 'Z → A' },
      ],
    },
    {
      type: 'section',
      sectionKey: 'date',
      label: 'Date',
      items: [
        { itemKey: 'date-newest', label: 'Newest first' },
        { itemKey: 'date-oldest', label: 'Oldest first' },
      ],
    },
  ]}
/>
```

## Item modifiers

Each `MenuItem` accepts:

- `icon` — a 16×16 leading icon.
- `shortcut` — trailing secondary text (typically a keybinding like `⌘K`).
- `description` — secondary line below the label.
- `isDanger` — text + hover background swap to the danger palette.
- `href` — render as `<a>` instead of `<button>`; both Enter and click navigate.
- `isDisabled` — skipped by keyboard; click is a no-op.

### MenuSection / MenuDivider

`MenuSection` accepts an optional `label` for a group title; `MenuDivider` renders a 1 px horizontal line as visual separator only — it isn't part of keyboard navigation.

<Callout variant="info" title="Accessibility">
  The trigger is wired to the menu via `aria-haspopup="menu"` + `aria-expanded` + `aria-controls`. Once open the menu is `role="menu"` (or `menu` + `menuitemcheckbox` for multiple). Arrow keys roam, Home / End jump to the ends, character keys do prefix matching, and Esc closes the menu and returns focus to the trigger.
</Callout>
