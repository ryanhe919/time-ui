# Tabs

Group related panels behind a row of selectable headers. Ships with three visual variants — `underline`, `pills`, `bordered` — in horizontal or vertical orientation. Supports both a declarative API (`<Tab>` + `<TabPanel>`) and a data-driven API (`items={[...]}`).

<Callout variant="info" title="Tabs vs SegmentedControl">
  Tabs are **navigation** semantics (`role="tablist"` + `role="tabpanel"`) — switching between panels of pre-existing content. For a one-of-many choice inside a form, reach for [`SegmentedControl`](/docs/components/segmented-control) instead — it has `radiogroup` semantics and participates in form submission. Tabs switch a **panel**; SegmentedControl switches a **value**.
</Callout>

## Basic usage

The declarative form: each `<Tab itemKey>` wraps a `<TabPanel>` describing what that tab shows.

<LiveDemo code={`<Tabs aria-label="Repository" defaultSelectedKey="readme">
  <Tab itemKey="readme" label="README">
    <TabPanel itemKey="readme">Project documentation.</TabPanel>
  </Tab>
  <Tab itemKey="issues" label="Issues">
    <TabPanel itemKey="issues">Filed bugs and requests.</TabPanel>
  </Tab>
  <Tab itemKey="prs" label="Pull requests">
    <TabPanel itemKey="prs">Open code reviews.</TabPanel>
  </Tab>
</Tabs>`}>
  <div style={{ width: '100%', maxWidth: 480 }}>
    <Tabs aria-label="Repository" defaultSelectedKey="readme">
      <Tab itemKey="readme" label="README">
        <TabPanel itemKey="readme">Project documentation.</TabPanel>
      </Tab>
      <Tab itemKey="issues" label="Issues">
        <TabPanel itemKey="issues">Filed bugs and requests.</TabPanel>
      </Tab>
      <Tab itemKey="prs" label="Pull requests">
        <TabPanel itemKey="prs">Open code reviews.</TabPanel>
      </Tab>
    </Tabs>
  </div>
</LiveDemo>

## Variants

`underline` (default) — a sliding hairline indicator. `pills` — pill-shaped selection inspired by macOS segmented controls. `bordered` — surrounds the panel with a hairline frame, useful when the panel stands on its own.

## Disabling tabs

`isDisabled` disables the whole control; `disabledKeys` disables specific tabs and arrow-key navigation skips them automatically.

<LiveDemo code={`<Tabs
  aria-label="Plan"
  defaultSelectedKey="free"
  disabledKeys={['team']}
  items={[
    { key: 'free',  label: 'Free' },
    { key: 'pro',   label: 'Pro' },
    { key: 'team',  label: 'Team (coming soon)' },
  ]}
/>`}>
  <Tabs
    aria-label="Plan"
    defaultSelectedKey="free"
    disabledKeys={['team']}
    items={[
      { key: 'free', label: 'Free' },
      { key: 'pro', label: 'Pro' },
      { key: 'team', label: 'Team (coming soon)' },
    ]}
  />
</LiveDemo>

## Lazy panels

With `isLazy`, only the active panel is mounted — others mount on first activation. Useful for heavy dashboards or panels that fetch on demand.

<LiveDemo code={`<Tabs
  aria-label="Dashboard"
  isLazy
  defaultSelectedKey="overview"
  items={[
    { key: 'overview',  label: 'Overview',  content: <Overview /> },
    { key: 'analytics', label: 'Analytics', content: <Analytics /> },  // mounts only when first selected
    { key: 'reports',   label: 'Reports',   content: <Reports /> },
  ]}
/>`}>
  <Tabs
    aria-label="Lazy demo"
    isLazy
    defaultSelectedKey="overview"
    items={[
      { key: 'overview', label: 'Overview', content: 'Overview is mounted.' },
      { key: 'analytics', label: 'Analytics', content: 'This panel mounts when first selected.' },
      { key: 'reports', label: 'Reports', content: 'Same — mounted on demand.' },
    ]}
  />
</LiveDemo>

<Callout variant="info" title="Accessibility">
  Renders native `role="tablist"` + `role="tab"` + `role="tabpanel"` with roving tabindex: arrow keys (`←` `→` horizontal, `↑` `↓` vertical) move selection, `Home` / `End` jump to ends, and disabled tabs are skipped. The sliding indicator honors `prefers-reduced-motion`. Always label the tablist via `aria-label` or `aria-labelledby` when there's no visible heading.
</Callout>
