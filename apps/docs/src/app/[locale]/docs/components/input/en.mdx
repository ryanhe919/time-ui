# Input

The core single-line text field. Four visual **variants**, six semantic **colors**, five size steps, plus `startContent` / `endContent` slots, `isClearable`, and a built-in password toggle.

Pass any of `label` / `description` / `errorMessage` and `Input` will implicitly wrap itself in a [`FormField`](./form-field) so label linking and `aria-describedby` just work.

## Variants

Four form-focused variants ordered by visual weight — `flat` is a soft tinted chip with a hairline edge; `bordered` is a clean neutral outline; `faded` combines a tinted ground with the strong border (the loudest of the soft variants); `underlined` keeps only a bottom rule for Material-style forms.

## Colors

Six semantic colors. `color` tints the **border, focus ring, and soft
background** — `bordered` / `faded` show it at rest; `flat` / `underlined`

## Clearable

`isClearable` reveals a ✕ button whenever the field has a value. Escape also clears (opt out with `clearOnEsc={false}`).

## Password toggle

`type="password"` renders an eye button by default — clicking flips between `text` and `password`. `aria-pressed` reflects the current visibility.

## Controlled usage

Controlled mode fires `onChange(value)` on every keystroke — with the **unwrapped string**, not the event. This demo combines email validation, password toggle, and clearable:

<LiveDemo code={`import { useState } from 'react';
import { Input, Stack } from '@timeui/react';

export function SignUpForm() {
  const [email, setEmail] = useState('');
  const [password, setPassword] = useState('');
  const emailInvalid = email.length > 0 && !email.includes('@');

  return (
    <Stack spacing={16}>
      <Input
        type="email"
        label="Email"
        value={email}
        onChange={setEmail}
        isClearable
        isRequired
        errorMessage={emailInvalid ? 'Please enter a valid email' : undefined}
      />
      <Input
        type="password"
        label="Password"
        value={password}
        onChange={setPassword}
        isRequired
      />
    </Stack>
  );
}`}>
  <InputFormDemo />
</LiveDemo>

<Callout variant="info" title="Accessibility">
  `ref` points at the native `<input>`. The label (via FormField) is linked to the input's `id`; `isInvalid` sets `aria-invalid="true"` and routes the error text through `aria-describedby`. Clear and password-toggle buttons default to `tabIndex={-1}` (configurable via `clearButtonTabIndex`) to avoid cluttering the Tab order. All transitions honour `prefers-reduced-motion`.
