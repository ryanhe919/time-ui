# MultiSelect

A **multi-value listbox** built on top of the same trigger / popover / search
skeleton as [`Select`](./select), but with **chip-based echo** in the trigger,
**checkbox indicators** on each option, and an optional **toolbar** for
*Select all* / *Clear* inside the popover.

Use `MultiSelect` when the user needs to pick **two or more** values from a
finite set (tags, categories, recipients…). Reach for `Select` when the
choice is mutually exclusive, and for native `<select multiple>` only when
your form must work with no JavaScript at all — `MultiSelect` ships full
keyboard, screen-reader, type-ahead and Backspace support that the native
control simply does not have.

Two ways to declare options: the declarative `items` array (preferred), or
`<MultiSelectOption>` / `<MultiSelectOptGroup>` children (whose props are
read at render time — they don't emit DOM themselves).

## Chip echo + `maxTagCount`

The trigger renders one [`Tag`](./tag) chip per selected value. To stop the
trigger from growing unboundedly you can clamp the visible chip count with
`maxTagCount`. Three modes are supported:

### `maxTagCount="responsive"` (default)

The trigger measures available width and folds the overflow into a `+N`
chip. Hover the `+N` chip to read the hidden labels (`title` attribute and
`aria-label="+N more: …"` make it accessible).

<LiveDemo code={`<MultiSelect
  aria-label="tags"
  isFullWidth
  defaultValue={['frontend', 'backend', 'devops', 'design', 'qa', 'ai']}
  items={[
    { value: 'frontend', label: 'Frontend' },
    { value: 'backend', label: 'Backend' },
    { value: 'devops', label: 'DevOps' },
    { value: 'design', label: 'Design' },
    { value: 'qa', label: 'QA' },
    { value: 'ai', label: 'AI / ML' },
  ]}
/>`}>
  <MultiSelect
    aria-label="tags"
    isFullWidth
    defaultValue={['frontend', 'backend', 'devops', 'design', 'qa', 'ai']}
    items={[
      { value: 'frontend', label: 'Frontend' },

### Custom `filterOption`

Override the default substring filter with any predicate — useful for
acronym matching, fuzzy search, value-based search, etc.

<LiveDemo code={`<MultiSelect
  isSearchable
  aria-label="country"
  placeholder="Try typing 'us' or 'jp'…"
  searchPlaceholder="Match by value or label…"
  isFullWidth
  filterOption={(input, item) => {
    const needle = input.toLowerCase();
    const label = typeof item.label === 'string' ? item.label.toLowerCase() : '';

  }}
  items={[
    { value: 'cn', label: 'China' },
    { value: 'us', label: 'United States' },
    { value: 'jp', label: 'Japan' },

    { value: 'de', label: 'Germany' },
    { value: 'fr', label: 'France' },
  ]}
/>`}>

    searchPlaceholder="Match by value or label…"
    isFullWidth
    items={[

## Toolbar — Select all / Clear

`showSelectAllInToolbar` mounts a thin toolbar above the listbox showing
`Selected N / M` plus a single text button. The button toggles between
**Select all** (when not all visible items are selected) and **Clear**
(when they are). The Clear here only removes *visible* items — to wipe
*everything* (including items hidden by search / `hideSelectedInList`),
prefer the trigger-side `isClearable` × button.

## Clearable

`isClearable` shows an × button on the right side of the trigger when
`value.length > 0`. Click it (or press `Esc` if `clearOnEsc` is enabled) to
wipe the selection. The clear button is **not** in the Tab sequence
(`tabIndex={-1}`) — the trigger stays the only Tab stop, just like
`Input.isClearable`.

<LiveDemo code={`<MultiSelect
  aria-label="fruit"
  isClearable
  defaultValue={['a', 'b']}
  items={[
    { value: 'a', label: 'Apple' },
    { value: 'b', label: 'Banana' },

## Disabled / read-only / loading

`isDisabled` greys out the trigger and blocks all interaction (including
chip removal and keyboard). `isReadOnly` keeps the popover openable and
keyboard-navigable but rejects every value change — useful when you want
users to *inspect* the current selection but not edit it. `isLoading`
replaces the listbox area with a `role="status"` placeholder.

## Native form integration

Pass a `name` prop and `MultiSelect` will emit one `<input type="hidden">`
per selected value, so `FormData` on the surrounding `<form>` carries the
selection without any glue code.

## Design note: why is the checkbox on the **left**?

In `Select` the chosen item shows a `✓` on the **right** because there is
exactly one selected row at any time — putting the indicator on the right
balances the row visually. Multi-select inverts that: every row could be
selected, every row needs an indicator. Aligning indicators to the **left
edge** lets the user scan a single column to read selection state at a
glance. This matches the established practice in W3C APG Listbox examples
and every major multi-select library (Ant Design, MUI, NextUI). It is an
intentional divergence from `Select`, not an inconsistency.

<Callout variant="info" title="Accessibility">
  The trigger is `role="combobox"` + `aria-haspopup="listbox"` +
  `aria-expanded` + `aria-controls`; the popover is `role="listbox"` with
  `aria-multiselectable="true"`; options are `role="option"` with
  `aria-selected` / `aria-disabled` and a stable id targeted by
  `aria-activedescendant`. Group headings are `role="group"` containers
  with their own `aria-labelledby`.

  Keyboard:
  - **`↑` / `↓`** moves the highlight (skips disabled options)
  - **`Home` / `End`** jumps to the first / last enabled option
  - **`Enter` / `Space`** toggles the highlighted option's selection
  - **`Esc`** closes the popover and returns focus to the trigger; on a
    closed trigger with `clearOnEsc`, it clears the value
  - **`Backspace`** on the trigger (or in an empty searchbox) removes the
    last selected chip
  - **Type-ahead** — typing printable characters within an 800 ms window
    builds a prefix and highlights the first matching label
  - **`Tab`** closes the popover and lets the browser take focus

  All transitions and animations honor `prefers-reduced-motion: reduce`.
</Callout>
