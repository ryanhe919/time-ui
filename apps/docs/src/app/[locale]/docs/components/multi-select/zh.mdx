# 多选 MultiSelect

**多值 listbox**——共用 [`Select`](./select) 的 trigger / popover / 搜索 / 键盘
骨架，但在 trigger 内用**chip 回显**已选值，每行选项左侧用 **checkbox 指示器**
表达选中状态，popover 顶部还能挂一条可选的 **toolbar** 提供 *全选 / 清空*。

何时用 `MultiSelect`：用户需要从一个有限集合中选**两个及以上**的值（标签、
分类、收件人……）。如果选项之间互斥用 [`Select`](./select)；只有当表单必须
在零 JS 环境下也工作时才用原生 `<select multiple>`——本组件提供原生控件
完全没有的键盘、屏幕阅读器、type-ahead 与 Backspace 删除支持。

数据源有两种写法：声明式 `items` 数组（推荐），或 `<MultiSelectOption>` /
`<MultiSelectOptGroup>` children（父组件读取 props 而非渲染为 DOM）。

## chip 回显 + `maxTagCount`

trigger 内每个已选值渲染为一颗 [`Tag`](./tag) chip。为了避免 trigger 无限撑高，
可以用 `maxTagCount` 控制可见 chip 数。三种模式：

### `maxTagCount="responsive"`（默认）

trigger 自动测量可用宽度并把超出的 chip 折成 `+N`。鼠标移到 `+N` chip 上可
以看到隐藏项的列表（同时设置了 `title` 与 `aria-label="+N more: …"`，对辅助
技术友好）。

<LiveDemo code={`<MultiSelect
  aria-label="tags"
  isFullWidth

### 自定义 `filterOption`

用任意谓词替换默认子串过滤——简称匹配、模糊搜索、按 value 搜索都能实现。

<LiveDemo code={`<MultiSelect
  isSearchable
  aria-label="country"
  placeholder="试试输入 'us' 或 'jp'…"
  searchPlaceholder="按 value 或 label 匹配…"
  isFullWidth
  filterOption={(input, item) => {
    const needle = input.toLowerCase();
    const label = typeof item.label === 'string' ? item.label.toLowerCase() : '';
    return item.value.toLowerCase().includes(needle) || label.includes(needle);
  }}
  items={[
    { value: 'cn', label: 'China' },
    { value: 'us', label: 'United States' },
    { value: 'jp', label: 'Japan' },
    { value: 'kr', label: 'South Korea' },
    { value: 'de', label: 'Germany' },
    { value: 'fr', label: 'France' },
  ]}
/>`}>
  <MultiSelect
    isSearchable
    aria-label="country"
    placeholder="试试输入 'us' 或 'jp'…"
    searchPlaceholder="按 value 或 label 匹配…"
    isFullWidth

## Toolbar——全选 / 清空

`showSelectAllInToolbar` 在 listbox 上方渲染一条工具栏：左侧文本 `Selected N / M`，
右侧是单按钮——当**当前可见**项尚未全部选中时显示 **Select all**，已全部选中
时切换为 **Clear**。这里的 Clear **只**移除当前可见项，不影响搜索 / `hideSelectedInList`

## 一键清空 Clearable

`isClearable` 在 trigger 右端渲染 × 按钮，当 `value.length > 0` 时显示。
点击它（或在 `clearOnEsc` 启用时按 `Esc`）即清空所有已选。清空按钮**不**进入
Tab 序列（`tabIndex={-1}`），保持 trigger 是唯一 Tab stop——与 `Input.isClearable`

## 禁用 / 只读 / 加载中

`isDisabled` 整体置灰、阻断所有交互（含 chip 删除、键盘）。`isReadOnly` 允许
打开 popover、键盘导航，但拒绝任何**变更**——适合「让用户*查看*当前选中、
但不允许修改」的场景。`isLoading` 时把 listbox 区域替换为 `role="status"` 占位。

传入 `defaultValue` 即为**非受控**——父组件不持有 state，仅在需要时通过
`onChange` 读取最新值：

<LiveDemo code={`<MultiSelect

  onChange={(v) => console.log('next value:', v)}
  items={[
    { value: 'a', label: 'Apple' },
    { value: 'b', label: 'Banana' },
    { value: 'c', label: 'Cherry' },
  ]}
/>`}>
  <MultiSelect
    aria-label="uncontrolled"
    defaultValue={['a']}
    items={[
      { value: 'a', label: 'Apple' },
      { value: 'b', label: 'Banana' },

## 设计决策：为什么 checkbox 在**左侧**？

`Select` 中已选项的 `✓` 在**右侧**，是因为任意时刻只有一行被勾——`✓` 在右侧
能让单行视觉重心更平衡。多选反过来：每行都可能被勾，每行都需要指示器。
把指示器**左对齐**让用户能在单一列里**纵向扫读**当前选中状态，符合
W3C APG Listbox 示例与所有主流多选库（Ant Design / MUI / NextUI）的惯例。
这是与 `Select` 的**有意分歧**，不是不一致。

<Callout variant="info" title="可访问性">
  trigger 为 `role="combobox"` + `aria-haspopup="listbox"` + `aria-expanded`
  + `aria-controls`；popover 为 `role="listbox"` 并带 `aria-multiselectable="true"`；
  选项为 `role="option"` 带 `aria-selected` / `aria-disabled` 与稳定 id（被
  `aria-activedescendant` 引用）。group 标题为 `role="group"` 容器并自带
  `aria-labelledby`。

  键盘：
  - **`↑` / `↓`** 切换高亮（自动跳过 disabled 项）
  - **`Home` / `End`** 跳到首/末个未禁用项
  - **`Enter` / `Space`** 切换当前高亮项的选中态
  - **`Esc`** 关闭 popover、焦点回 trigger；trigger 已关闭且开启 `clearOnEsc` 时清空数值
  - **`Backspace`** 在 trigger（或空搜索框）上按下会移除最后一颗 chip
  - **Type-ahead**——800 ms 内累积可打印字符为前缀，匹配第一个 label 起始命中的项
  - **`Tab`** 关闭 popover 并把焦点交给浏览器

  所有 transition 与 animation 都遵循 `prefers-reduced-motion: reduce`。
</Callout>
