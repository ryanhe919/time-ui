# Card

A generic container primitive: wrap one piece of information or a small cluster of controls. Three variants (flat / bordered / elevated), six colours, five sizes, an optional accent bar, and opt-in hover / pressable / link behaviour. `CardHeader` / `CardBody` / `CardFooter` are opt-in structural subcomponents — use them when semantics matter.

<Callout variant="info" title="Card vs. StatCard">
  - **Card** — an open container. Put whatever you want inside; you decide the semantics.
  - **StatCard** — a KPI-shaped derivative with built-in label + value + delta pill + optional trend slot.
</Callout>

## Basic usage

The default is `variant='bordered'`. Compose content with `CardHeader` / `CardBody` / `CardFooter`. All three are optional — Card wraps arbitrary children by itself.

<LiveDemo code={`<Card>
  <CardHeader title="Project Aurora" subtitle="Production" />
  <CardBody>
    <Text size="sm" color="secondary">Healthy for 12 days.</Text>
  </CardBody>
  <CardFooter justify="end">
    <Button size="sm" variant="bordered">View details</Button>
  </CardFooter>
</Card>`}>

    <Card>

## Pressable

`isPressable` turns the whole card into a focusable target that responds to click, Enter, and Space — the callback lives on `onPress`. `isHoverable` is visual-only; it does not add keyboard semantics. `color='primary'` drives the hover border / ring colour.

<LiveDemo previewSource="children" code={`<Card isPressable color="primary" onPress={() => setCount(c => c + 1)}>
  <CardHeader title="Pressable card" subtitle="Click / Enter / Space fires onPress" />
  <CardBody>
    <Text size="sm" color="secondary">Press count: <strong>{count}</strong></Text>
  </CardBody>
</Card>
<Card isHoverable>
  <CardHeader title="Hoverable only" subtitle="isHoverable is visual only" />
</Card>`}>

</LiveDemo>

## As a link

Passing `href` renders the root as an `<a>` (unless `as` overrides it) and implicitly marks the card pressable. When `target='_blank'` and `rel` is omitted, the component fills in `noopener noreferrer` automatically.

<LiveDemo code={`<Card
  href="https://react.dev"
  target="_blank"
  rel="noreferrer"
  aria-label="Read the React docs"
  variant="elevated"
>
  <CardHeader title="React docs" subtitle="react.dev ↗" />
  <CardBody>
    <Text size="sm" color="secondary">The whole card is one anchor with native keyboard behaviour.</Text>
  </CardBody>
</Card>`}>
  <div style={{ width: 'min(360px, 100%)' }}>
    <Card
      href="https://react.dev"

      aria-label="Read the React docs"

## Disabled

`isDisabled` on a pressable card dims the surface to 0.55 opacity, sets `cursor: not-allowed` and `aria-disabled='true'`; keyboard activation and `onPress` are blocked.

<LiveDemo code={`<Card
  isPressable
  isDisabled
  color="primary"
  onPress={() => console.log('never fires')}
>
  <CardHeader title="Disabled" subtitle="onPress will not fire" />
</Card>`}>
  <div style={{ width: 'min(320px, 100%)' }}>
    <Card isPressable isDisabled color="primary">
      <CardHeader title="Disabled" subtitle="onPress will not fire" />
    </Card>
  </div>
</LiveDemo>

## Caveats

<Callout variant="info" title="color is not always visible">
  A Card defaults to a neutral look. `color` only affects visuals when (a) `accentBar !== 'none'` (it drives the bar colour) or (b) the card is `isPressable` / `isHoverable` (it drives hover border / ring / background). A static `<Card color='primary'>` looks exactly like `color='default'`.
</Callout>

<Callout variant="info" title="onPress vs. onClick">
  **Prefer `onPress`**: the component normalises mouse click and keyboard Enter / Space into one callback. `onClick` still forwards the native event but keyboard activation does not synthesise one. When `isDisabled` is true `onPress` is blocked; `onClick` can still fire from the underlying event — so wire business callbacks to `onPress` for predictable semantics.
</Callout>

<Callout variant="info" title="Do not nest a primary action inside a pressable card's footer">
  A pressable card is already the focus target. Placing a primary Button in the footer creates two focus stops and ambiguous Enter behaviour. Either keep the primary action in the footer (and leave the card non-pressable) or put only a secondary link inside the footer of a pressable card.
</Callout>

<Callout variant="info" title="Accessibility">
  Renders a `<div>` by default; rendering `<a>` when `href` is present picks up native anchor semantics. When pressable on a non-native focusable tag the component adds `role='button'` + `tabIndex=0` and handles Enter / Space. `isDisabled` sets `aria-disabled='true'` and blocks `onPress`. Under `prefers-reduced-motion` the hover / press transitions and the accent-bar width animation are suppressed.
</Callout>
