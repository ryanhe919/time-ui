# Modal

A centered modal dialog: focus trap + body scroll lock + Esc dismissal + overlay click-out + return focus on close. Portaled into `<body>`, with a saturate(180%) blurred-glass overlay. Five width steps (`sm` / `md` / `lg` / `xl` / `full`) and two scroll behaviours (`inside` / `outside`).

<Callout variant="info" title="Modal vs. Drawer vs. Popover">
  - **Modal** — interrupts the current task to demand confirmation or critical input. Locks body scroll and traps focus.
  - **Drawer** — a parallel side panel (settings, details) you observe alongside the main flow.
  - **Popover** — a lightweight, anchor-positioned overlay (menu, hint card).
</Callout>

## Sizes

`sm` 420 px / `md` 560 px (default) / `lg` 720 px / `xl` 960 px / `full` viewport-spanning (with a 16 px gutter). Every size is bounded by `max-width: calc(100vw - 32px)` and `max-height: calc(100vh - 64px)`, so nothing overflows on small viewports.

## Compound usage

Beyond the convenience `title` / `footer` props, you can split the body into the semantic `<ModalHeader>` / `<ModalBody>` / `<ModalFooter>` subcomponents — same default tokens, but you're free to drop in icons, subtitles, or rich form controls. **Note**: don't combine `<ModalHeader>` with the top-level `title` prop; both will render.

```tsx
<Modal isOpen={open} onOpenChange={setOpen}>
  <ModalHeader>Compose message</ModalHeader>
  <ModalBody>
    <Input placeholder="Subject" />
    <Textarea placeholder="Body" rows={5} />
  </ModalBody>
  <ModalFooter>
    <Button variant="ghost">Cancel</Button>
    <Button>Send</Button>
  </ModalFooter>
</Modal>
```

## Dismissal behaviour

- `closeOnEsc` (default `true`) — Esc closes the dialog.
- `closeOnOverlayClick` (default `true`) — clicking the translucent overlay closes the dialog.
- `showCloseButton` (default `true`) — a 32×32 close icon in the top-right with a hover background and a `focus-visible` outline.

Disable all three to get a **forced-flow** dialog that can only be dismissed via the buttons you provide ("I agree" etc.) — useful for one-off compliance acknowledgement.

```tsx
<Modal
  isOpen={open}
  onOpenChange={setOpen}
  closeOnEsc={false}
  closeOnOverlayClick={false}
  showCloseButton={false}
  title="Terms updated"
  footer={<Button onClick={() => setOpen(false)}>I agree</Button>}
>
  We have updated our Terms of Service. You must agree to continue.
</Modal>
```

## Scroll behaviour

- **`inside`** (default) — total panel height is bounded by `max-height`; header and footer stay pinned, **only the body scrolls**. Best for long forms or long copy.
- **`outside`** — the entire panel scrolls with the page (panel height is content-driven). Best for shorter, page-like content.

```tsx
<Modal scrollBehavior="inside" title="Release notes">
  {/* header / footer pinned, body scrolls with a custom scrollbar */}
  <p>{longText}</p>
</Modal>

<Modal scrollBehavior="outside" title="Release notes">
  {/* whole panel scrolls */}
  <p>{longText}</p>
</Modal>
```

### ModalHeader / ModalBody / ModalFooter

All three share the same signature and accept `children` / `className` / `id`. `ModalHeader` renders as an `<h2>`; `ModalFooter` lays out children with `flex` + `justify-content: flex-end` + a default gap.

<Callout variant="info" title="Accessibility">
  The panel is `role="dialog"` + `aria-modal="true"`; supplying `title` automatically sets `aria-labelledby` to its element. While open, Tab / Shift+Tab cycles within the panel (focus trap), body scroll is locked, and focus returns to the previously focused element on close. Under `prefers-reduced-motion` the panel transition collapses to a simple fade.

## Best practices

- **Use a Modal** for irreversible actions, confirmations, or focused side-flows (creating an item, confirming a delete, signing in). Modals interrupt — make sure the user notices the change of context.
- **Use a Drawer** when the user wants to edit details while still seeing the surrounding context (e.g. the right-hand inspector in a three-column layout).
- **Use a Popover** for trigger-attached lightweight overlays (menus, share sheets, notifications).
- Two simultaneous Modals is an anti-pattern — fold the second into the first or move to a multi-step form.
- Keep one clear focus target inside complex Modals. By default `autoFocus` lands on the first focusable element, so avoid surprise inputs in the body.
