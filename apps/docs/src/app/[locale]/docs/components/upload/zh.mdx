# 文件上传 Upload

把文件选择（点击触发）与拖拽（dropzone）统一在一个组件里，自动维护上传队列、进度、成功 / 失败状态；支持受控 / 非受控、图片预览、并发控制与自定义请求。

两种外观：默认的按钮触发（`variant='button'`）与大块拖拽区（`variant='dropzone'`）。无论哪种，文件列表（`UploadList`）都会在下方显示选择结果。

### 模拟进度

传入 `customRequest` 的场景里，上传进度由调用方调用 `handlers.onProgress(percent)` 推送。下面的 demo 用 `setInterval` 每 160ms 推进 10% 模拟真实进度。

<LiveDemo previewSource="children" code={`import { Upload } from '@timeui/react';
import type { UploadRequest } from '@timeui/react';

const simulatedRequest: UploadRequest = ({ signal }, handlers) => {
  let percent = 0;
  const timer = setInterval(() => {
    if (signal.aborted) {
      clearInterval(timer);
      return;
    }
    percent = Math.min(100, percent + 10);
    handlers.onProgress(percent);
    if (percent >= 100) {
      clearInterval(timer);
      handlers.onSuccess({ ok: true });
    }
  }, 160);
  return () => clearInterval(timer);
};

export function Demo() {
  return <Upload multiple customRequest={simulatedRequest} />;
}`}>
  <UploadWithProgressDemo />
</LiveDemo>

## 校验

### 只收图片

`accept` 的语义与原生 `<input type="file">` 保持一致（MIME 通配 / 后缀列表）。收到图片时组件会自动生成本地 `previewUrl`。

<LiveDemo code={`<Upload accept="image/*" multiple />`}>
  <Upload accept="image/*" multiple />
</LiveDemo>

### 大小限制

`maxSize` 以**字节**为单位。不符合的文件会经 `onReject` 回调告诉你，带上拒绝原因（`'size'`）与可选的 i18n 默认消息。

<LiveDemo previewSource="children" code={`import { Upload, useToast } from '@timeui/react';
import type { UploadRejection } from '@timeui/react';

export function Demo() {
  const toast = useToast();
  const handleReject = (rejections: UploadRejection[]) => {
    for (const r of rejections) {
      toast.show({
        status: 'danger',
        title: '上传被拒绝',
        description: r.message ?? r.file.name + ' (' + r.reason + ')',
      });
    }
  };
  return (
    <Upload
      multiple
      maxSize={2 * 1024 * 1024}
      onReject={handleReject}
      description="单文件最大 2 MB。"
    />
  );
}`}>
  <UploadRejectDemo />
</LiveDemo>

## 自定义

### 自定义请求（真实 XHR 骨架）

真实项目里 `customRequest` 就是上传的出口：拿到 `File` 对象，发你自己的 fetch / XHR，按情况调 `handlers.onProgress` / `onSuccess` / `onError`。下面的 demo 并不会真的发请求（demo 内是 `setTimeout` 模拟，一半概率失败），但代码里给了 XHR 的典型写法可供复制。

<LiveDemo previewSource="children" code={`import { Upload } from '@timeui/react';
import type { UploadRequest } from '@timeui/react';

const uploadRequest: UploadRequest = ({ file, signal }, handlers) => {
  const xhr = new XMLHttpRequest();
  xhr.open('POST', 'https://example.com/upload');
  xhr.upload.onprogress = (e) => {
    if (e.lengthComputable) handlers.onProgress(Math.round((e.loaded / e.total) * 100));
  };
  xhr.onload = () => {
    if (xhr.status >= 200 && xhr.status < 300) {
      handlers.onSuccess(xhr.response);
    } else {
      handlers.onError(new Error('HTTP ' + xhr.status));
    }
  };
  xhr.onerror = () => handlers.onError(new Error('Network error'));
  signal.addEventListener('abort', () => xhr.abort());

  const form = new FormData();
  form.append('file', file);
  xhr.send(form);
};

export function Demo() {
  return <Upload multiple customRequest={uploadRequest} />;
}`}>
  <UploadCustomRequestDemo />
</LiveDemo>

### beforeUpload 预校验

`beforeUpload` 在**单个文件**即将进入队列前触发，返回 `false` / `Promise<false>` 则该文件被拒（`reason === 'before-upload'`）。适合做自定义规则：文件名、魔数、签名等。

<LiveDemo previewSource="children" code={`import { Upload, useToast } from '@timeui/react';
import type { UploadRejection } from '@timeui/react';

export function Demo() {
  const toast = useToast();
  return (
    <Upload
      multiple
      beforeUpload={(file) => !/secret/i.test(file.name)}
      onReject={(rejections: UploadRejection[]) => {
        for (const r of rejections) {
          if (r.reason === 'before-upload') {
            toast.show({
              status: 'warning',
              title: '文件名包含敏感词',
              description: r.file.name,
            });
          }
        }
      }}
      description='示例：文件名包含 "secret"（大小写不敏感）会被拦下。'
    />
  );
}`}>
  <UploadBeforeUploadDemo />
</LiveDemo>

### 自定义列表项渲染

`renderItem` 可完全接管单个文件的显示。它传入 `(file, actions)`，`actions.remove` / `actions.retry` 帮你触发标准行为。下面的 demo 展示图片缩略图 + 自定义胶囊删除按钮。

<LiveDemo previewSource="children" code={`import { Upload } from '@timeui/react';
import type { UploadFile } from '@timeui/react';

export function Demo() {
  return (
    <Upload
      multiple
      accept="image/*"
      renderItem={(file: UploadFile, actions) => (
        <li key={file.id} className="my-upload-item">
          {file.previewUrl && <img src={file.previewUrl} alt="" />}
          <span>{file.name}</span>
          <button type="button" onClick={actions.remove}>Remove</button>
        </li>
      )}
    />
  );
}`}>

### 受控用法

`value` + `onChange` 让你全权管理文件列表；`useRef<UploadHandle>` 还能从外部调 `open()` / `clear()` / `submit()` / `retry()` / `abort()`。

<LiveDemo previewSource="children" code={`import { useRef, useState } from 'react';
import { Upload, Button } from '@timeui/react';
import type { UploadFile, UploadHandle } from '@timeui/react';

export function Demo() {
  const [files, setFiles] = useState<UploadFile[]>([]);
  const handleRef = useRef<UploadHandle>(null);

  return (
    <>
      <Upload ref={handleRef} multiple value={files} onChange={setFiles} />
      <Button onClick={() => handleRef.current?.open()}>打开文件选择器</Button>
      <Button onClick={() => handleRef.current?.clear()}>清空</Button>
    </>
  );
}`}>
  <UploadControlledDemo />
</LiveDemo>

## 注意事项

<Callout variant="warning" title="使用 customRequest 时请连通取消信号">
  组件会给 `customRequest` 一个 `AbortSignal`，调用 `handle.abort(id)` 或组件卸载时会触发它。**你需要自己把这个 signal 接到 fetch / XMLHttpRequest 上**（例如 `xhr.addEventListener('abort', …)` 或 `fetch(url, { signal })`），否则 HTTP 请求不会真正中断。
</Callout>

<Callout variant="info" title="拖拽中的校验仅凭 accept 类型">
  浏览器在 `dragenter` / `dragover` 阶段只能读到 MIME 类型，拿不到文件大小。因此 dropzone 的 `data-rejecting` 预拒态**只会**依据 `accept` 不匹配判定；超过 `maxSize` 或 `maxCount` 等约束必须等到真正 drop 后才能判断——那时会走 `onReject` 而不是视觉高亮。
</Callout>

<Callout variant="info" title="Safari < 14 的 data-rejecting 可能不准确">
  早期 Safari 对 `DataTransferItem.type` 处理不一致，某些情况下无法提前识别类型不符的文件。建议关键场景依赖 `onReject` 的事后反馈，而不是仅仅依靠 dropzone 的高亮。
</Callout>
