# Upload

File picking (click to open) and drag-and-drop (dropzone) unified in one
component, with an auto-managed upload queue, per-file progress, and
success / error state. Supports controlled / uncontrolled usage, image
preview, concurrency control, and a custom request hook.

Two shapes: the default button trigger (`variant='button'`) and a large
drop target (`variant='dropzone'`). In both, the `UploadList` beneath
shows the selected files.

### Simulated progress

When a `customRequest` is provided, upload progress is pushed by the
caller via `handlers.onProgress(percent)`. The demo below uses
`setInterval` to advance 10% every 160ms, simulating real upload
progress.

<LiveDemo code={`import { Upload } from '@timeui/react';
import type { UploadRequest } from '@timeui/react';

const simulatedRequest: UploadRequest = ({ signal }, handlers) => {
  let percent = 0;
  const timer = setInterval(() => {
    if (signal.aborted) {
      clearInterval(timer);
      return;
    }
    percent = Math.min(100, percent + 10);
    handlers.onProgress(percent);
    if (percent >= 100) {
      clearInterval(timer);
      handlers.onSuccess({ ok: true });
    }
  }, 160);
  return () => clearInterval(timer);
};

export function Demo() {
  return <Upload multiple customRequest={simulatedRequest} />;
}`}>
  <UploadWithProgressDemo />
</LiveDemo>

## Validation

### Images only

`accept` shares its semantics with the native `<input type="file">`
(MIME globs or extension lists). For images, the component generates a
local `previewUrl` automatically.

<LiveDemo code={`<Upload accept="image/*" multiple />`}>
  <Upload accept="image/*" multiple />

### Size limit

`maxSize` is expressed in **bytes**. Over-sized files are reported via
`onReject` with `reason === 'size'` and a localized default message.

<LiveDemo code={`import { Upload, useToast } from '@timeui/react';
import type { UploadRejection } from '@timeui/react';

export function Demo() {
  const toast = useToast();
  const handleReject = (rejections: UploadRejection[]) => {
    for (const r of rejections) {
      toast.show({
        status: 'danger',
        title: 'Upload rejected',
        description: r.message ?? r.file.name + ' (' + r.reason + ')',
      });
    }
  };
  return (
    <Upload
      multiple
      maxSize={2 * 1024 * 1024}
      onReject={handleReject}
      description="Max 2 MB per file."
    />
  );
}`}>
  <UploadRejectDemo />
</LiveDemo>

## Customization

### Custom request (real XHR skeleton)

In a real project `customRequest` is your upload outlet — you receive
the `File`, run your own fetch / XHR, and call `handlers.onProgress` /
`onSuccess` / `onError`. The demo below does **not** actually send a
request (it's a `setTimeout` sim that fails half the time), but the code
string shows a typical XHR implementation you can paste.

<LiveDemo code={`import { Upload } from '@timeui/react';
import type { UploadRequest } from '@timeui/react';

const uploadRequest: UploadRequest = ({ file, signal }, handlers) => {
  const xhr = new XMLHttpRequest();
  xhr.open('POST', 'https://example.com/upload');
  xhr.upload.onprogress = (e) => {
    if (e.lengthComputable) handlers.onProgress(Math.round((e.loaded / e.total) * 100));
  };
  xhr.onload = () => {
    if (xhr.status >= 200 && xhr.status < 300) {
      handlers.onSuccess(xhr.response);
    } else {
      handlers.onError(new Error('HTTP ' + xhr.status));
    }
  };
  xhr.onerror = () => handlers.onError(new Error('Network error'));
  signal.addEventListener('abort', () => xhr.abort());

  const form = new FormData();
  form.append('file', file);
  xhr.send(form);
};

export function Demo() {
  return <Upload multiple customRequest={uploadRequest} />;
}`}>
  <UploadCustomRequestDemo />
</LiveDemo>

### beforeUpload pre-check

`beforeUpload` fires **per file** before it enters the queue. Returning
`false` / `Promise<false>` rejects it (`reason === 'before-upload'`).
Good for bespoke rules: filename patterns, magic numbers, signatures.

<LiveDemo code={`import { Upload, useToast } from '@timeui/react';
import type { UploadRejection } from '@timeui/react';

export function Demo() {
  const toast = useToast();
  return (
    <Upload
      multiple
      beforeUpload={(file) => !/secret/i.test(file.name)}
      onReject={(rejections: UploadRejection[]) => {
        for (const r of rejections) {
          if (r.reason === 'before-upload') {
            toast.show({
              status: 'warning',
              title: 'Filename blocked',
              description: r.file.name,
            });
          }
        }
      }}
      description='Demo: any filename containing "secret" (case-insensitive) is blocked.'
    />
  );
}`}>
  <UploadBeforeUploadDemo />
</LiveDemo>

### Controlled usage

`value` + `onChange` puts the list under your control; a
`useRef<UploadHandle>` also exposes imperative `open()` / `clear()` /
`submit()` / `retry()` / `abort()`.

<LiveDemo code={`import { useRef, useState } from 'react';
import { Upload, Button } from '@timeui/react';
import type { UploadFile, UploadHandle } from '@timeui/react';

export function Demo() {
  const [files, setFiles] = useState<UploadFile[]>([]);
  const handleRef = useRef<UploadHandle>(null);

  return (
    <>
      <Upload ref={handleRef} multiple value={files} onChange={setFiles} />
      <Button onClick={() => handleRef.current?.open()}>Open picker</Button>
      <Button onClick={() => handleRef.current?.clear()}>Clear</Button>
    </>
  );
}`}>
  <UploadControlledDemo />
</LiveDemo>

## Caveats

<Callout variant="warning" title="Wire the abort signal when using customRequest">
  The component hands `customRequest` an `AbortSignal`; it fires on
  `handle.abort(id)` or when the component unmounts. **You need to wire
  that signal to your fetch / XMLHttpRequest yourself** (e.g.
  `xhr.addEventListener('abort', …)` or `fetch(url, { signal })`),
  otherwise the actual HTTP request won't be cancelled.
</Callout>

<Callout variant="info" title="Drag-time validation only checks accept">
  During `dragenter` / `dragover` browsers only expose the MIME type —
  not the file size. The dropzone's `data-rejecting` pre-check therefore
  only reflects `accept` mismatches; `maxSize` / `maxCount` can only be
  evaluated once the drop actually happens, at which point `onReject`
  fires (no visual highlight).
</Callout>

<Callout variant="info" title="data-rejecting is unreliable on Safari < 14">
  Older Safari versions expose `DataTransferItem.type` inconsistently,
  so the pre-drop rejection highlight may not fire. For critical flows,
  rely on post-drop feedback through `onReject` rather than the
  dropzone's highlight.
</Callout>

  The button variant is a native `<button>`; the dropzone is

  Space. The list is `role="list"` with per-item remove / retry buttons
  (each carrying readable labels from `@timeui/core`'s zh / en i18n).
  Under `prefers-reduced-motion`, the progress bar switches state
  without animating.
