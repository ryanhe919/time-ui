# Radio

Single-select. `Radio` **must** live inside a `RadioGroup` — the group hands each child a shared `name` and the current `value` via context, so native radio-group keyboard arrows and form submission behave correctly.

## Basic usage

<LiveDemo code={`<RadioGroup label="Gender" defaultValue="female">
  <Radio value="female">Female</Radio>
  <Radio value="male">Male</Radio>
  <Radio value="other">Other</Radio>
</RadioGroup>`}>
  <RadioGroup label="Gender" defaultValue="female">
    <Radio value="female">Female</Radio>
    <Radio value="male">Male</Radio>
    <Radio value="other">Other</Radio>
  </RadioGroup>
</LiveDemo>

<Callout variant="info" title="Accessibility">
  RadioGroup renders `<fieldset>` + `<legend>` (or `role="radiogroup"` + `aria-labelledby` for ReactNode labels). Keyboard: Tab focuses the currently selected radio, then `↑ / ↓ / ← / →` cycle through the group (native behavior). Disabled items are skipped. A `Radio` rendered outside a `RadioGroup` logs a dev warning — use a native `<input type="radio">` instead for that case.
</Callout>
