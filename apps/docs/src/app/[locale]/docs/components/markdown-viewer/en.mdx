# Markdown Viewer

A document-oriented markdown reader built on `react-markdown` + `remark-gfm`. Designed for long-form content: reading-friendly typography, optional table of contents, copy / download / refresh toolbar, and either inline strings or remote URL sources. Distinct from [`ChatMarkdown`](../chat/markdown), which is tuned for streaming chat fragments — `MarkdownViewer` owns its own scroll container, layout, and chrome. Distributed behind the `@timeui/react/markdown-viewer` subpath export so `react-markdown` / `remark-gfm` **stay out of the main bundle** unless the page actually renders the viewer.

## Installation

`MarkdownViewer` is shipped as an independent sub-entry. Install the optional peers first:

```bash
npm install @timeui/react react-markdown remark-gfm
```

Then import from the sub-entry (recommended):

```tsx
import { MarkdownViewer } from '@timeui/react/markdown-viewer';
```

MarkdownViewer is **only** available from the `@timeui/react/markdown-viewer` subpath — it is intentionally not re-exported from the main `@timeui/react` entry so that bundlers can keep `react-markdown` / `remark-gfm` out of pages that never render long-form markdown.

## Basic usage

Pass a markdown string via `source`. By default, `sourceType` is `'content'`, so the string is rendered as-is. Fenced code blocks are delegated to TimeUI's [`CodeBlock`](./code-block) for shiki-powered syntax highlighting.

<MarkdownViewerBasicDemo />

```tsx
import { MarkdownViewer } from '@timeui/react/markdown-viewer';

const md = `# Welcome
Hello, **TimeUI**!`;

export function Demo() {
  return <MarkdownViewer source={md} />;
}
```

## Loading from a URL

Switch `sourceType` to `'url'` and pass a fetch-able URL or path. The viewer shows a built-in spinner while loading and renders an inline error state on failure. The toolbar's refresh button becomes active in URL mode and re-fetches the document via an internal nonce — handy for "regenerate" flows.

```tsx
<MarkdownViewer
  sourceType="url"
  source="/docs/changelog.md"
  fetchOptions={{ headers: { 'cache-control': 'no-cache' } }}
  onLoad={(text) => console.log('loaded', text.length)}
  onError={(err) => console.error(err)}
/>
```

> Note: `fetchOptions` is intentionally not part of the effect dependency list. To force a re-fetch from the consumer, change `source` / `sourceType`, or call the toolbar's refresh button (which bumps an internal refresh nonce).

## Table of contents

Pass `showToc` to render a sticky TOC alongside the document. Headings are extracted directly from the markdown source (SSR-friendly — the TOC is available before client hydration). Active section tracking uses `IntersectionObserver` against the viewer's own scroll container, so it never fights the page's scroll position.

<MarkdownViewerTocDemo />

```tsx
<MarkdownViewer
  source={md}
  showToc
  tocPosition="right"  // or "left"
  tocMaxDepth={3}
/>
```

## Toolbar

The default toolbar exposes:

- **Copy** — copies the raw markdown to the clipboard.
- **Download** — saves the markdown as a `.md` file.
- **Refresh** — re-fetches the document (URL mode only; hidden in content mode).

Pass a `toolbar` config to hide individual buttons, or `showToolbar={false}` to drop the header entirely:

```tsx
<MarkdownViewer source={md} toolbar={{ download: false, refresh: false }} />
<MarkdownViewer source={md} showToolbar={false} />
```

Toolbar labels (including the "Copied!" confirmation) can be overridden via `toolbarLabels` for i18n.

## Links

Internal anchors (`#heading-slug`) scroll within the viewer's container and never mutate `location.hash`. External links (`http://`, `https://`, `mailto:`, …) honour `linkTarget` (`'_blank'` by default with `rel="noreferrer noopener"`). Intercept any click via `onLinkClick` to wire up SPA routing — calling `event.preventDefault()` skips the default behaviour.

```tsx
<MarkdownViewer
  source={md}
  linkTarget="_self"
  onLinkClick={(href, event) => {
    if (href.startsWith('/internal/')) {
      event.preventDefault();
      router.push(href);
    }
  }}
/>
```

## Custom renderers

Override any `react-markdown` node via `components`. User overrides win over the built-ins, so you can replace headings, anchor handling, lists, etc. without losing the slug-id behaviour for unaffected nodes.

```tsx
<MarkdownViewer
  source={md}
  components={{
    img: ({ src, alt }) => <img src={src} alt={alt} loading="lazy" />,
  }}
/>
```

```ts
interface MarkdownViewerToolbarConfig {
```

<Callout variant="info" title="Bundle impact">
  `react-markdown` and `remark-gfm` are **not** bundled with `@timeui/react`. Install them as optional peers and import from the dedicated subpath — `import { MarkdownViewer } from '@timeui/react/markdown-viewer'` — so pages that never render long-form markdown remain lighter. MarkdownViewer is intentionally **not** exported from the main entry to keep the core barrel lean.
</Callout>

<Callout variant="info" title="MarkdownViewer vs ChatMarkdown">
  `MarkdownViewer` owns its own scroll container, toolbar, and TOC — use it for documentation pages, changelogs, README dialogs, and any "render the whole document" UX. For streaming chat fragments rendered into a parent message bubble, reach for [`ChatMarkdown`](../chat/markdown) instead, which is intentionally chrome-less.
</Callout>

<Callout variant="info" title="Accessibility">
  The wrapper carries `role="article"`, mirrors `aria-label` from props, and toggles `aria-busy` while loading. Errors render with `role="alert"`. Headings get deterministic slug ids, and TOC items are real anchors with `aria-current="true"` on the active section. Reduced-motion users get instant scroll-to-anchor instead of smooth scrolling.
</Callout>
