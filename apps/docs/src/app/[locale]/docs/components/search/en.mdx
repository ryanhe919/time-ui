# Search

A pill-shaped **search trigger** — visually an input, **semantically a `<button>`**.
Clicking it opens a command palette / search dialog (your responsibility).
The placeholder defaults to `useI18n().search.placeholder` and follows the
active locale automatically.

<Callout variant="warning" title="It is not a typable input">
  `Search` does **not** accept text input. It's a trigger button: clicking it
  opens a dialog which hosts the actual editable field and results. This "⌘K
  command palette" pattern is the same approach used by Apple, Vercel, Tailwind,
  and Linear — the header "search box" only opens the palette.
  <br />
  For a truly editable search field, use a native `<input type="search">` or
  wait for the upcoming `SearchInput` component.
</Callout>

<Callout variant="info" title="Accessibility">
  Renders a native `<button type="button">`; `aria-label` defaults to `placeholder`. Keyboard focusable with a visible outline, and all animation honors `prefers-reduced-motion`. The hosted dialog is responsible for focusing its inner input and handling <kbd>Esc</kbd>.
</Callout>

## Best practices

- Never pass `value` to `Search` — it's a button, not an input.
- For the command palette: auto-focus the inner `<input>` on open, close on <kbd>Esc</kbd>, and set `role="dialog"` + `aria-modal="true"`.
- If you just need a conventional search field (not a command palette), use a native `<input type="search">`; a dedicated `SearchInput` component is on the roadmap.
