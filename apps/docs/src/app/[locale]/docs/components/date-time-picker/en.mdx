# Date Time Picker

`DateTimePicker` extends `DatePicker` with a side-by-side time column so a single control covers year-month-day **and** hour-minute-second. Minute and second columns are opt-in — fields you hide stay fixed at `0` in the emitted `Date`, so downstream consumers always receive a complete `Date` object.

<Callout variant="info" title="Calendar on the left, time on the right">
  The panel reuses the shared `CalendarPanel` (same keyboard shortcuts, min/max, `isDateUnavailable`) and pairs it with a `TimePanel` — three optional listboxes for Hour / Minute / Second, plus an AM/PM column when `is12Hour` is on. A `[Now] [Clear] [OK]` footer lets you stage changes as a draft; the value only commits on **OK**, which avoids accidental onChange storms while you spin the time columns.
</Callout>

## Basic usage

By default the picker opens Hour + Minute columns and emits a `Date` whose seconds are `0`. `isClearable` adds a clear button in the input and in the footer.

<LiveDemo code={`import { useState } from 'react';
import { DateTimePicker } from '@timeui/react';

export function Demo() {
  const [value, setValue] = useState<Date | null>(null);
  return (
    <DateTimePicker
      value={value}
      onChange={setValue}
      placeholder="Pick a date and time"
      isClearable
    />
  );
}`}>
  <DateTimePickerBasicDemo />
</LiveDemo>

## Granularity — hide minutes or seconds

Toggle the time columns via `showMinute` (default `true`) and `showSecond` (default `false`). **Hidden fields are forced to `0` when the value is committed** — this is the whole point of the opt-in model: pick the precision you want, and never worry about stray `getSeconds() === 37` leaking out.

<LiveDemo code={`// hour only — minute & second are always 0
<DateTimePicker showMinute={false} />

// hour + minute (default)
<DateTimePicker />

// hour + minute + second
<DateTimePicker showSecond />`}>
  <DateTimePickerGranularityDemo />
</LiveDemo>

## 12-hour mode

`is12Hour` adds a fourth AM/PM column. The value is still a native `Date` (24-hour internally); only the formatting and the listbox change.

```tsx
<DateTimePicker is12Hour isClearable />
```

## Stepping through time

`hourStep` / `minuteStep` / `secondStep` (default `1`) thin out the listbox options — useful for appointment windows or log aggregation granularity.

```tsx
<DateTimePicker minuteStep={15} secondStep={10} />
```

## Commit flow — draft + OK

Unlike `DatePicker` (where picking a day closes the panel), `DateTimePicker` treats the panel as a staging area. Clicking a day or spinning the time columns updates an internal draft; `onChange` only fires when you press **OK**. This keeps the UX sane for multi-step adjustments. If you prefer instant commits, wire `onChange` to your own state and drive the picker with `isOpen` / `onOpenChange`.

Footer buttons:
- **Now** fills the draft with today + the current time (still respects `minValue` / `maxValue`).
- **Clear** (only when `isClearable`) wipes the value and closes the panel.
- **OK** commits the draft and closes the panel.

## Localisation and formatting

- `locale` — BCP-47 tag forwarded to `Intl`.
- `format(d)` / `parse(s)` — override the input text round-trip. The default format is `YYYY-MM-DD HH:mm` (with `:ss` and ` AM/PM` appearing when those switches are on); the default parser accepts the same shape plus raw ISO-8601 as a fallback.

  Each time column is a `listbox` with `option` children so screen readers announce the selected hour / minute / second alongside the date grid.
