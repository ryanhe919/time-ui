# Popover

An anchor-positioned floating container: 12 placements, four trigger modes (`click` / `hover` / `focus` / `manual`), portal rendered, with built-in header / footer / arrow and Esc + outside-click dismissal. Controlled and uncontrolled both ship; positioning lives in `position: fixed` and tracks scroll / resize.

<Callout variant="info" title="Popover or Tooltip?">
  A Popover hosts **rich content** — forms, buttons, link lists. Its panel is focusable and clickable, and may carry a header / footer. A Tooltip is just a **monochrome inverted hint**, `pointer-events: none`, hidden on touch. Use Tooltip for hover-triggered one-liners; use Popover for click-to-expand cards.
</Callout>

## Basic usage

`anchor` accepts a `ReactElement` or a render prop. The component clones the element to inject a `ref` plus the events for the active trigger; existing `onClick` / `onMouseEnter` etc. are preserved and chained.

<LiveDemo code={`<Popover anchor={<Button>Open</Button>}>
  Hello, popover.
</Popover>`}>
  <Popover anchor={<Button>Open</Button>}>Hello, popover.</Popover>
</LiveDemo>

## Trigger modes

`click` (default) / `hover` / `focus` / `manual`. In `manual` the component stops listening to anchor events entirely — open state is whatever you pass to `isOpen`.

## Header & footer

`header` renders a bold title at the top of the panel; `footer` renders a secondary text or button row at the bottom. Both are optional. Providing `header` automatically sets `aria-labelledby`, so screen readers announce the popover title.

<LiveDemo code={`<Popover
  header="Notifications"
  footer={<a>View all →</a>}
  anchor={<Button>Inbox</Button>}
>
  You have 3 new notifications.
</Popover>`}>

## Arrow toggle (`hasArrow`)

Defaults to `true` — an 8 px rotated square is rendered on the side facing the anchor. Set to `false` for card-style popovers without a beak.

<Callout variant="info" title="Accessibility">
  In `click` mode the anchor automatically receives `aria-haspopup="dialog"` + `aria-expanded` + `aria-controls`. The panel is `role="tooltip"` for `hover` triggers, otherwise `role="dialog"`. `closeOnEsc` listens both at the window level and on the panel, so focus can be anywhere. All animation respects `prefers-reduced-motion`.
</Callout>

## Best practices

- Use `trigger="click"` whenever the panel contains real interactions (inputs, multiple buttons) — hover is too fragile.
- For hover triggers, keep the anchor focusable (e.g. a `<button>`) so keyboard users can reach the panel.
- Don't nest a Popover inside another Popover. For multi-level UI use a Modal.
- Need imperative open from elsewhere? Use `trigger="manual"` plus a controlled `isOpen` — both `closeOnEsc` and `closeOnBlur` become no-ops in manual mode, so dismissal is fully yours.
